## Contracts and classification

Pure `evaluatePlan(input, ruleset)` produces both alternatives, issues, rejected smaller candidates, applied criteria, assumptions, materials and versions. Input strings retain decimal-comma drafts; Zod rejects invalid numeric values. Reliable nameplate current takes precedence; P/V is only for confirmed resistive loads. When P and I coexist, no numerical tolerance is invented: a separate evidenced nameplate consistency check is required.

Known failed applicable checks or exhausted supported candidates block; otherwise missing critical calculation input means draft; results plus open checks mean preliminary; all covered criteria and required professional checks satisfied means validated for execution preparation. Engine review status stays pending even if an individual plan is validated. Failed checks take precedence over missing data. Not-applicable is accepted only for RCD applicability and with a justification; essential checks cannot be waived. Measured/calculated upstream drop and professional attestations remain distinct evidence types.

Every technical edit clears positive dependent confirmations (all global checks conservatively; each route alternative's own feasibility). Failed findings persist until explicitly reassessed. Ruleset or engine changes clear positive attestations upon reopen; no persisted result is trusted. Raw draft records are schema-versioned in transactional Dexie migrations. Corrupt/future records fail visibly rather than being overwritten. PDF snapshots clone the exact evaluation and raw inputs before asynchronous font loading.

## Review and release gate

Automated tests and source extraction are developer checks, not independent professional approval. Pilot release requires signed engineering review of the extracted tables, resistance model, breaker assumptions, reference cases, status rules, and electrician usability/performance testing. Keep engine/PDF review banners until that gate is actually met.
